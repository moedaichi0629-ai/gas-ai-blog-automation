# AIブログ記事自動生成ツール 要件定義

※ 本ドキュメントは模擬案件の要件定義です。背景・課題は案件設定上の想定です。

## 1. 背景

クラウド勤怠管理ツール「キンタイ Cloud」を提供する BtoB SaaS 企業（想定）では、オウンドメディアで SEO 記事を継続的に発信し、見込み顧客の獲得を目指している。

## 2. クライアントの課題（想定）

- SEO記事の執筆に時間がかかり、公開本数を増やせない
- キーワードごとに記事の構成・トーンを揃えるのが難しい
- キーワード・記事・公開状況の管理がばらばらになりやすい

## 3. 目的

- Googleスプレッドシートでキーワードを管理し、そこから記事の下書きを自動生成することで、執筆の初稿作成にかかる工数を減らす
- 生成した記事は人間が確認・編集する前提とし、品質の最終判断は人が行う
- 将来的に WordPress へ下書きとして登録できる設計にしておく

## 4. システム構成

```
Googleスプレッドシート
   ↓（選択行のキーワード）
Google Apps Script
   ↓
Claude API（記事生成）
   ↓（JSONで返答）
Google Apps Script（解析・シートへ書き込み）

※ 将来：Google Apps Script → WordPress REST API（下書き投稿）
```

## 5. 機能要件

| No. | 機能 | 内容 |
|---|---|---|
| F-1 | メニュー追加 | スプレッドシートを開いたときに「記事生成」メニューを追加し、その中に「選択行の記事を生成」を置く |
| F-2 | 選択行の取得 | 選択中の範囲の一番上の行を処理対象とする。1行目（見出し行）は処理しない |
| F-3 | キーワード取得 | A列（キーワード）・B列（サブキーワード）を取得する。キーワードが空欄の場合はエラーを表示して終了する。サブキーワードは任意 |
| F-4 | 上書き確認 | F列（記事本文）に値がある場合は、再生成して上書きしてよいか確認する |
| F-5 | 記事生成 | Claude API に記事生成を依頼し、タイトル・本文・メタディスクリプションを JSON で受け取る |
| F-6 | JSON解析 | コードフェンスの除去、JSON部分の切り出し、`JSON.parse()`、必須項目（title / content / metaDescription）の存在確認を行う |
| F-7 | シートへの書き込み | D列にタイトル、F列に本文、G列にメタディスクリプションを書き込む |
| F-8 | ステータス管理 | 生成開始時に C列を「生成中」、完了時に「生成済み」、エラー時に「生成エラー」にする |
| F-9 | 文字数チェック | 生成後、本文の文字数が 2,000〜3,000文字の範囲外なら完了ダイアログに警告を表示する（自動再生成はしない） |
| F-10 | エラー表示 | エラー内容をダイアログと実行ログに表示する |
| F-11 | 接続テスト | `testClaudeApi()` で Claude API に短いテストメッセージを送り、結果を実行ログに表示する |
| F-12 | WordPress payload確認 | `testWordPressPayload()` で選択行の D・F・G列から WordPress 用 payload を作成し、実行ログに表示する（送信はしない） |

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| セキュリティ | APIキーはコードに書かず、Script Properties（`CLAUDE_API_KEY`）から取得する。APIキーはログに出力しない |
| 安全性 | WordPress 用 payload の status は `draft` 固定。`draft` 以外ならエラーで停止する |
| 実行時間 | GAS の実行時間制限（6分）内に収まるよう、1回の実行で1記事のみ生成する |
| 保守性 | 列番号・ステータス文言・API設定・WordPress設定をコード冒頭の設定値（`CONFIG` / `STATUS` / `CLAUDE_CONFIG` / `WP_CONFIG`）にまとめる |
| 可読性 | 初心者でも読めるよう、コードに日本語コメントを付ける |

## 7. シート構成

1行目は見出し行。2行目以降に1行1記事。

| 列 | 項目 | 備考 |
|---|---|---|
| A | キーワード | 必須 |
| B | サブキーワード | 任意 |
| C | ステータス | ツールが書き込み |
| D | タイトル | ツールが書き込み |
| E | WordPress URL | 現在は未使用（将来用） |
| F | 記事本文 | ツールが書き込み（Markdown形式） |
| G | メタディスクリプション | ツールが書き込み |

## 8. 記事仕様

| 項目 | 内容 |
|---|---|
| 媒体 | 「キンタイ Cloud」オウンドメディア向け SEO 記事 |
| ターゲット | 中小企業の経営者・IT担当者 |
| 執筆者の役割 | BtoB SaaS のマーケティングライター |
| 文字数 | 本文 2,000〜3,000文字（目標 2,200〜2,700文字） |
| 構成 | タイトル／導入（約300字）／H2 × 3／まとめ（約200字、H2見出し） |
| キーワード | メインキーワードを不自然にならない範囲で含める。サブキーワードも可能な範囲で含める |
| トーン | カジュアルだが専門性がある。専門知識がない読者にも分かる文章 |
| トーンマナー | 参考記事の文体・構成・語りかけ方を参考にする（内容はコピーしない） |
| 事実の扱い | 断定しすぎない。統計データ・具体的な数値・法令の細かな条文・製品の具体的な機能や料金など、確認できない情報を作り出さない |
| 本文の形式 | Markdown（H2見出しは `## `、段落は空行で区切る。タイトルは本文に含めない） |
| メタディスクリプション | 120字以内（プロンプトで指示） |
| 画像 | 画像生成・画像挿入は対象外 |
| 位置づけ | AI生成後に人間が確認・編集する下書き |

## 9. ステータス

| ステータス | 設定するタイミング | 設定者 |
|---|---|---|
| 未生成 | 記事生成前（空欄でも可） | 利用者が手入力 |
| 生成中 | 記事生成の開始時 | ツール |
| 生成済み | 記事の書き込み完了時（文字数が範囲外でも「生成済み」） | ツール |
| 生成エラー | 生成処理の途中でエラーが発生したとき | ツール |
| 投稿済み | WordPress 投稿後（将来用） | 現在は使用しない |

## 10. Claude API

| 項目 | 内容 |
|---|---|
| エンドポイント | `https://api.anthropic.com/v1/messages` |
| API バージョン | `2023-06-01`（`anthropic-version` ヘッダー） |
| モデル | `claude-sonnet-4-6` |
| 認証 | `x-api-key` ヘッダー。キーは Script Properties の `CLAUDE_API_KEY` から取得 |
| max_tokens | 記事生成：8,000／接続テスト：100 |
| 通信 | `UrlFetchApp.fetch()`（`muteHttpExceptions: true`） |
| 出力形式 | `title` / `content` / `metaDescription` の3項目のみを持つ JSON |
| エラー判定 | HTTP ステータス 200 以外、`stop_reason` が `max_tokens`（返答が途中で切れた）または `refusal`（返答拒否）の場合はエラー |

## 11. WordPress 連携

| 項目 | 内容 |
|---|---|
| 現在の実装 | payload の作成と実行ログへの表示のみ（`testWordPressPayload()`） |
| payload | `{ title, content, status: "draft", excerpt }` |
| 各項目の元データ | title = D列、content = F列（Markdownのまま）、excerpt = G列 |
| status | `draft` 固定（`publish` にはしない） |
| 将来の送信先 | `https://example-saas.co.jp/wp-json/wp/v2/posts`（例示）へ POST する想定 |
| 将来の認証 | WordPress のアプリケーションパスワードを想定。認証情報は Script Properties に保存する想定 |

## 12. 今回の実装範囲

- F-1〜F-12 の機能すべて
- WordPress 用 payload の作成・ログ確認まで

## 13. 実装しないもの

- WordPress への実送信（`UrlFetchApp.fetch()` による WordPress API 呼び出し）
- WordPress の認証情報（ユーザー名・アプリケーションパスワード・API URL）の設定
- E列（WordPress URL）への書き込み、「投稿済み」ステータスの設定
- Markdown から HTML への変換
- 文字数が範囲外・JSON が壊れた場合などの自動再生成
- 複数行の一括生成
- 画像生成・画像挿入

## 14. 既知の制限

- **開いているシートが処理対象になる。** 別のシートを開いて実行すると、そのシートに書き込まれる。
- **複数行を選択しても、一番上の1行だけを処理する。**
- **GAS の実行時間制限などで処理が強制終了した場合、C列が「生成中」のまま残る**（「生成エラー」にならない）。
- **再生成に失敗した場合、以前の記事が D・F・G列に残ったまま C列が「生成エラー」になる。**
- **メタディスクリプションの120字以内はプロンプトでの指示のみ**で、GAS 側では文字数をチェックしていない。
- 本文の文字数は JavaScript の文字数（`length`）で数えるため、見出し記号（`## `）や改行も1文字として数える。
- プロンプトで JSON 形式を指示しているが、Claude の返答が不正な JSON になり解析エラーになる可能性はゼロではない。
- 1記事の生成に時間がかかった場合、通信のタイムアウトでエラーになる可能性がある。
